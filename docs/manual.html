목소리 고르기

처음 한 번만 하면 됩니다. 정해두면 이후 모든 편에 같은 목소리가 쓰입니다.

Actions 탭 → 목소리 들어보기 → Run workflow

받는 곳을 헷갈리기 쉽습니다. 왼쪽 워크플로 이름을 누른 화면에는 Artifacts가 없습니다. 그 화면의 목록에서 방금 돌린 실행을 한 번 더 눌러 들어가야 맨 아래에 나옵니다.

마이크로소프트가 제공하는 한국어 목소리는 세 개뿐입니다. 그래서 목소리마다 말 속도와 음높이를 바꾼 세 가지 톤을 함께 뽑아 모두 아홉 가지를 들려줍니다. 같은 목소리라도 낮고 느리게 읽으면 꽤 다르게 들립니다.

톤속도음높이느낌
기본-5%+0Hz표준
낮고 느리게-14%-10Hz무게가 실립니다. 신화 나레이션에 어울립니다
조금 빠르게+4%+0Hz가볍고 진행이 빠릅니다

목록을 코드에 박아두지 않고 매번 물어보기 때문에, 목소리가 새로 나오면 자동으로 후보에 들어옵니다.

실행 화면 맨 아래 Artifacts에서 목소리-샘플을 받으세요. 파일 이름이 08_남성_InJoon_낮고느리게.mp3 처럼 번호·성별·이름·톤 순이라 위에서부터 차례로 들으면 됩니다. 읽는 데 걸린 시간도 함께 나오는데, 짧을수록 빨리 읽는 목소리입니다.

실행 화면 요약에 번호마다 넣을 세 줄이 그대로 나옵니다. config.json에 옮겨 적으면 끝입니다.

"tts_voice": "ko-KR-InJoonNeural",
"tts_rate":  "-14%",   ← 말 속도. 음수가 느림
"tts_pitch": "-10Hz"   ← 음높이. 음수가 낮음

목소리나 톤을 바꾸면 다음 조립 때 음성이 자동으로 다시 만들어집니다. 설정만 고치고 예전 음성이 그대로 쓰이는 일은 없습니다.

읽어볼 문장을 직접 넣을 수도 있습니다. 실제 1화 도입부를 넣어보면 그 목소리가 이 채널에 맞는지 더 정확히 판단됩니다.

편당 작업 순서

2화부터는 이 다섯 단계만 반복합니다. 코드는 건드리지 않습니다.

  1. 이미지 올리기약 2분

    사파리에서 저장소를 열고 input/images 폴더로 들어갑니다.

    Add file → Upload files → 사진 28장 선택 → Commit changes

    지난 편 이미지가 남아 있으면 먼저 지웁니다.

  2. 대본 넣기약 1분

    input/script.json을 열고 연필 아이콘을 눌러 내용을 갈아 끼운 뒤 Commit changes.

  3. 점검부터 한 번40초

    Actions → 영상 만들기 → Run workflow
  점검만 하고 끝내기  ☑

    이미지와 대본이 맞는지, 빠진 번호는 없는지 40초 만에 알려줍니다. 6분짜리 조립을 돌려놓고 3분 뒤에 오류를 보는 것보다 낫습니다.

  4. 조립4~6분

    체크를 풀고 다시 Run workflow. 쇼츠도 같이 뽑으려면 쇼츠로 뽑을 컷 칸에 3-8처럼 넣습니다.

    이 동안 아이패드를 꺼도 됩니다. 서버에서 도는 작업입니다.

  5. 받기약 1분

    Actions 목록에서 방금 돌린 실행을 눌러 들어간 뒤, 맨 아래 Artifacts에서 완성본을 받습니다. zip이라 파일 앱에서 한 번 누르면 풀립니다.

    워크플로 이름만 누른 화면에는 Artifacts가 없습니다. 실행 하나를 골라 들어가야 합니다.

Actions 탭이 안 보이면 사파리 주소창 왼쪽 ᴀA → 데스크탑용 웹사이트 요청.

대본 쓰는 법

input/script.json 한 파일입니다.

{
  "title": "1화 아버지를 삼킨 아들, 아들을 삼킨 아버지",
  "accent_color": "#4DD9C6",
  "bgm": "bgm.mp3",
  "cuts": [
    {
      "n": 1,
      "narration": "아무것도 없었습니다. 진짜로, 아무것도요.",
      "motion": "zoom_in"
    },
    {
      "n": 2,
      "narration": "그 텅 빈 어둠의 이름이 카오스였습니다.",
      "motion": "pan_left",
      "sfx": "thunder.mp3"
    }
  ],
  "ending_card": "다음 편, 신들의 전쟁."
}

길이 계산

컷 길이는 고정이 아닙니다. 나레이션 음성의 실제 길이를 재서 여백 0.4초를 더한 값이 그 컷의 길이가 됩니다. 말이 끝나면 화면이 넘어갑니다.

대본을 쓸 때는 글자 하나당 0.2초로 잡으면 맞습니다.

대본 분량영상 길이
1,000자약 3분 20초
1,500자약 5분 00초
2,000자약 6분 40초

엔딩 카드 3초가 여기에 더 붙습니다.

자막

narration만 쓰면 됩니다. 읽는 문장이 그대로 자막이 됩니다. 자막이 뜨는 시각은 어림잡는 게 아니라, 음성을 만들 때 받아오는 낱말별 발음 시각에 맞춥니다.

한 줄 20자를 넘으면 어절 단위로 줄바꿈하고, 두 줄을 넘으면 자막을 두 번에 나눠 띄웁니다. 이미지는 건드리지 않습니다.

자막을 따로 줄여 쓰면 subtitle 항목을 넣을 수 있지만, 그러면 어느 낱말에 해당하는지 알 수 없어 자막 시각이 글자 수 어림 계산으로 떨어집니다. 점검 단계에서 어느 컷이 그런지 알려줍니다.

카메라 움직임

값화면쓸 만한 데
zoom_in서서히 확대긴장이 올라갈 때, 인물에 집중
zoom_out서서히 축소전체가 드러날 때, 장면 전환
pan_left왼쪽으로 이동넓은 풍경, 시선 이동
pan_right오른쪽으로 이동같은 용도, 방향만 반대
pan_up위로 이동하늘·높이를 보여줄 때
pan_down아래로 이동땅속·추락

같은 방향을 계속 쓰면 단조롭습니다. 확대와 축소를 번갈아 두면 화면이 살아납니다.

이미지 준비

파일 이름

기본은 cut01.png ~ cut28.png입니다. 번호가 곧 등장 순서이고, 번호가 하나라도 빠지면 에러로 멈춥니다. 조용히 건너뛰지 않습니다.

사진앱에서 IMG_4821.png 같은 이름 그대로 올리고 싶으면 config.json의 image_naming을 "ordered"로 바꾸세요. 파일명을 숫자까지 따져 정렬한 순서대로 1번 컷부터 배정합니다 (IMG_2가 IMG_10보다 앞).

이 경우 이미지 개수와 대본 컷 수가 정확히 같아야 하고, 어떤 그림이 몇 번 컷이 되었는지 점검 단계에서 표로 보여줍니다. 반드시 한 번 훑어보세요.

컷  1  ←  IMG_7.png
컷  2  ←  IMG_14.png
컷  3  ←  IMG_21.png

형식과 비율

  • png · jpg · webp를 씁니다
  • HEIC는 열 수 없습니다. 아이폰 사진의 기본 형식입니다. 설정 → 카메라 → 포맷 → 높은 호환성으로 바꾸거나, 올리기 전에 PNG로 저장하세요. 섞여 있으면 조립을 시작하지 않고 파일 이름을 알려줍니다
  • 이미지를 자르거나 늘리지 않습니다. 16:9가 아니면 검은 여백이 들어가고, 점검 단계에서 어느 컷인지 알려줍니다
  • 1920×1080 이상을 권합니다. 카메라가 8% 확대되므로 작은 그림은 흐려집니다

배경음악과 효과음

배경음악

input/ 폴더에 bgm.mp3라는 이름으로 올리면 자동으로 깔립니다. .m4a .wav .ogg .flac .aac도 됩니다. 다른 이름을 쓰려면 대본의 bgm 항목에 파일명을 적으세요.

영상보다 짧으면 반복해서 채웁니다. 볼륨은 15%이고, 나레이션이 나오는 동안 스스로 더 작아집니다(더킹). 말이 끝나면 다시 올라옵니다.

bgm_duck나레이션 중 낮아지는 정도
light4dB — 음악을 살리고 싶을 때
medium8dB — 기본값
strong12dB — 말이 가장 또렷해집니다

효과음

input/sfx/ 폴더를 만들어 파일을 넣고, 대본의 해당 컷에 이름을 적습니다.

{ "n": 5, "narration": "…", "motion": "zoom_in", "sfx": "thunder.mp3" }

그 컷이 시작하는 순간에 재생됩니다. 볼륨은 sfx_volume (기본 0.6)으로 조절합니다.

첫 1초는 어둠에서 밝아지고, 마지막 2초는 어둠으로 잠깁니다.

쇼츠 뽑기

롱폼에서 고른 구간만 9:16 세로로 다시 만들어 냅니다. 잘라내는 게 아니라 세로 화면 기준으로 새로 그리기 때문에 자막이 읽을 만한 크기로 들어갑니다.

Actions → 영상 만들기 → Run workflow
  쇼츠로 뽑을 컷   3-8

3-8처럼 범위로도, 3,5,9처럼 하나씩도 됩니다. 40초(shorts.max_seconds)를 넘으면 넘치는 컷은 빼고 어느 컷이 빠졌는지 알려줍니다. 음성은 롱폼에서 만든 것을 다시 쓰므로 빠릅니다.

shorts.background가로 그림을 세로에 담는 방식
blur배경을 흐리게 깔고 그 위에 원본. 화면이 꽉 차면서 그림은 안 잘립니다 (기본)
pad위아래를 검게 비웁니다
crop가운데만 남기고 좌우를 잘라냅니다. 그림이 잘립니다

결과물이 남는 곳

Artifact내용
완성본유튜브에 올릴 mp4 하나. 대본 제목이 파일 이름이 됩니다
컷별-클립과-음성컷별 개별 클립(mp4)과 나레이션(mp3)

컷별 클립을 남기는 이유는 이 도구가 실패해도 작업이 0이 되지 않게 하기 위해서입니다. 완성본이 마음에 안 들면 그 클립들을 캡컷으로 가져가 손으로 이어 붙일 수 있습니다.

실행 화면 위쪽 요약에 총 길이·컷 수·자막 폰트가 표시되고, summary.json에는 자막 시각이 낱말 단위로 잡혔는지까지 기록됩니다.

1.15 이하로 낮추세요.

오류가 아니라 알림입니다. 그대로 진행되지만 자막 시각이 어림 계산이 됩니다. 정확히 맞추려면 대본에서 subtitle을 빼세요.

그 밖의 문제는 실행 화면의 빨간 단계를 눌러 마지막 몇 줄을 확인하세요. 조립이 중간에 멈춰도 그때까지 만들어진 음성과 클립은 남습니다.

컴퓨터에서 쓰기

윈도우·맥·리눅스에서 직접 돌릴 수도 있습니다. 결과물은 완전히 같습니다.

# 처음 한 번만
sudo apt-get install -y ffmpeg fonts-noto-cjk   # mac: brew install ffmpeg
pip3 install -r requirements.txt

# 매번
python3 build.py --check          # 이미지와 대본 점검
python3 build.py                  # 조립
python3 build.py --shorts 3-8     # 쇼츠
python3 build.py --voice-sample   # 목소리 전부 뽑기
옵션뜻
--check점검만 하고 끝냅니다
--fresh이미 만든 음성도 다시 만듭니다
